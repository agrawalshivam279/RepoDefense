## 1. Executive Summary & Objective

In **Step 4.1a**, we designed and migrated the persistent relational and vector database layer (`user_skills` and `candidate_weaknesses` tables, `4c8d1e2f3a4b` Alembic migration with Supabase public schema RLS lockdown) along with Pydantic v2 schemas (`UserSkillBase/Create/Update/Response`, `CandidateWeaknessBase/Create/Update/Response`, `UserSkillsOverviewResponse`).

In **Step 4.1b**, we build the business logic service and REST API layer:
1. **`WeaknessTrackerService`** (`backend/app/services/weakness_tracker.py`):
   - Ingests evaluation turn outcomes from any of the 6 RepoDefense simulation modes (`core_defense`, `pr_defense`, `commit_defense`, `incident_simulation`, `stress_test`, `arch_defense`).
   - Automatically maintains candidate `UserSkill` records: updates proficiency scores (exponential moving average: $0.7 \times \text{prior} + 0.3 \times \text{new\_score}$ clamped $[0.0, 100.0]$), increments evaluation counters (`total_evaluations`, `passed_evaluations`, `failed_evaluations`), and records evaluation timestamps.
   - When an evaluation fails (`passed=False`), extracts and records a `CandidateWeakness` record, dynamically computing a 384-dimensional vector embedding for the weakness topic using `generate_embeddings([topic])` from `backend/app/analyzers/embeddings.py` (with deterministic fallback).
   - Provides weakness resolution workflow (`resolve_weakness`) marking gaps resolved with timestamp and mentor follow-up advice while reinforcing candidate skill proficiency.
   - Calculates aggregated portfolio overviews (`get_user_skills_overview`) including KPI counters, average proficiency, weak vs. strong skill segmentation (70% threshold), and prioritized unresolved gap lists.
2. **FastAPI Skills REST API** (`backend/app/api/v1/skills.py`):
   - Exposes authenticated endpoints:
     - `GET /api/v1/skills/overview`: returns `UserSkillsOverviewResponse` for the authenticated candidate.
     - `GET /api/v1/skills/weaknesses`: returns filtered list of `CandidateWeaknessResponse` (with optional `project_id`, `resolved`, and `category` filters).
     - `PATCH /api/v1/skills/weaknesses/{id}/resolve`: marks an active weakness as resolved with optional mentor feedback notes.
     - `POST /api/v1/skills/evaluations`: records an evaluation turn result and updates candidate skill proficiencies.
   - Mounted in `backend/app/main.py` under prefix `/api/v1/skills`.
3. **Hermetic Test Suite** (`backend/tests/test_weakness_tracker.py`):
   - Comprehensive unit and API contract tests with 100% statement coverage.

## 4. Architectural Design & API Contracts

### 4.1 Scoring Algorithm for `UserSkill` Proficiency
When an evaluation turn is recorded:
- If no existing `UserSkill` exists for `(user_id, category, topic)`:
  - Initial `proficiency_score = clamp(score, 0.0, 100.0)`.
  - `total_evaluations = 1`.
  - `passed_evaluations = 1 if passed else 0`.
  - `failed_evaluations = 0 if passed else 1`.
- If an existing record exists:
  - `proficiency_score = round(current_score * 0.7 + score * 0.3, 1)`.
  - `total_evaluations += 1`.
  - `passed_evaluations += 1` if `passed` else `failed_evaluations += 1`.
  - `last_evaluated_at = datetime.now(timezone.utc)`.

### 4.2 Severity Derivation
If severity tier is not explicitly supplied by the caller:
- `score < 35.0` $\to$ `WeaknessSeverity.CRITICAL`
- `score < 65.0` $\to$ `WeaknessSeverity.MAJOR`
- `score >= 65.0` $\to$ `WeaknessSeverity.MINOR`

### 4.3 Weakness Resolution Workflow
When calling `resolve_weakness`:
- Validates `user_id` ownership (returns 404 if not found or unauthorized).
- Sets `resolved = True`, `resolved_at = datetime.now(timezone.utc)`.
- If `feedback` provided, appends or updates `feedback`.
- Re-scores associated `UserSkill`: boosts `proficiency_score = min(100.0, score + 10.0)`.

### 4.4 REST Endpoints Specification
- **`GET /api/v1/skills/overview`**:
  - Auth: Supabase JWT Bearer Token (`current_user`).
  - Response: `UserSkillsOverviewResponse` (200 OK).
- **`GET /api/v1/skills/weaknesses`**:
  - Auth: Supabase JWT Bearer Token (`current_user`).
  - Query params: `project_id: Optional[UUID]`, `resolved: Optional[bool]`, `category: Optional[str]`, `limit: int = 50`.
  - Response: `List[CandidateWeaknessResponse]` (200 OK).
- **`PATCH /api/v1/skills/weaknesses/{id}/resolve`**:
  - Auth: Supabase JWT Bearer Token (`current_user`).
  - Body: `CandidateWeaknessUpdate`.
  - Response: `CandidateWeaknessResponse` (200 OK) or 404 if not found.
- **`POST /api/v1/skills/evaluations`**:
  - Auth: Supabase JWT Bearer Token (`current_user`).
  - Body: Evaluation recording request.
  - Response: Dict containing updated `UserSkillResponse` and optional `CandidateWeaknessResponse`.

## 5. Implementation Sequence

1. **Implement `backend/app/services/weakness_tracker.py`**:
   - `record_evaluation_turn`: atomic upsert on `UserSkill`, vector embedding via `generate_embeddings`, conditional `CandidateWeakness` insertion.
   - `resolve_weakness`: multi-tenant safe update and skill boost.
   - `get_user_skills_overview`: KPI counters, skill categorization (weak $< 70\%$, strong $\ge 70\%$), top 5 unresolved weaknesses.
   - `get_candidate_weaknesses`: filtered weakness queries with pagination limit.
2. **Implement `backend/app/api/v1/skills.py`**:
   - Create router with dependencies `get_current_user` and `get_db`.
   - Wire endpoints to `WeaknessTrackerService` methods.
3. **Register Router in `backend/app/main.py`**:
   - Mount router under `f"{settings.API_V1_STR}/v1/skills"`.
4. **Author Tests in `backend/tests/test_weakness_tracker.py`**:
   - Unit tests covering scoring formulas, vector dimension extraction, weakness creation, resolution logic, and multi-tenant isolation.
   - Endpoint contract tests for overview, list, resolution, and evaluation intake.
